Feature Redundancy: Why Individual Importance Can Be Misleading

When similar features compete for credit, evaluating them as a group reveals what truly drives the model.

Summary

The study in brief

After training a model, the usual next question is which inputs (features) it relies on. The answer guides which features to keep, which to drop, and how to explain the model. This study shows that the standard answer goes wrong when several features carry the same information, such as a stock's 20-day and 60-day volatility. The model's credit gets split among them, and each one looks unimportant even when together they drive the model.

The study first uses made-up data where the true drivers are known. Adding 30 near-copies of 5 true drivers cuts the drivers' measured importance to 17% of its real value. Grouping features that move together, and testing each group as a whole, recovers the true drivers and their true ranking. On 90 US stocks, the same group test shows that past prices help predict how big a stock's next 10-day move will be, and do not help predict whether the stock will beat its peers.

Why it matters

  • Dropping "weak" features can remove the signal. A feature with close relatives looks about five times weaker than it is. A rule like "keep the top half" can throw away the very information the model uses.
  • A ranking is not proof of a signal. On a target where nothing could be predicted, one common method still gave 81% of its credit to the real features.
  • Random features make a good ruler. Adding a few columns of pure random numbers shows how big a score is when a feature carries nothing at all.
  • It changes what the stock features are good for. Price history helps forecast how much a stock will move, which matters for sizing positions and setting risk limits. It does not help pick which stocks will do better.

The problem · Similar features share the credit

Picture three people on a project who all know how to do the same task. To find out how important each one is, you remove one person at a time and see how much the project suffers. Each time, the other two cover the task, so the project barely notices. You conclude that none of them matters much. Remove all three together and the project fails, because the task is no longer done by anyone.

A model with similar features behaves the same way. A stock's 20-day volatility and its 60-day volatility both measure how jumpy the stock has been; a stock that was jumpy last month was usually jumpy over the last three months as well. When the model is tested without one of them, it leans on the other and loses almost nothing. Each volatility feature then looks minor, although volatility as a whole may be the most useful thing the model knows. This is called the substitution effect.

The study asks four questions:

  1. How much importance does a true driver lose when copies of it are present?
  2. Does testing similar features as a group give the right answer?
  3. Is there a quick check that works on real data, where the right answer is unknown?
  4. What do price features actually predict for US stocks, and which ones do the work?

The data · A made-up test with a known answer, then real stocks

Dataset 1: made-up data where the answer is known

On real data nobody knows which features truly matter, so a method cannot be graded there. The study therefore builds a dataset where the answer is known by construction. It has 10,000 rows and a yes/no label, and 40 features of three kinds:

  • 5 true drivers (named I_0 to I_4). The label is built from these.
  • 30 copies (R_0 to R_29). Each copy is one driver plus a little random noise, so it moves almost exactly with its driver (correlation 0.97). Each driver has between 4 and 8 copies. They carry no new information, just like a 15-day momentum feature added next to 10-day and 21-day momentum.
  • 5 noise features (N_0 to N_4). Pure random numbers, unrelated to the label.

A good importance method should score the drivers and their copies high and the noise at zero, and it should rank the five drivers in their true order.

Dataset 2: 90 US large-cap stocks

Daily adjusted prices for 90 large US stocks from Jan 2015 to Oct 2026, from Yahoo Finance. Every 5 trading days, each stock gets one row: its 15 features on that date and what happened over the next 10 days. That gives 48,690 rows (stock-dates). Every feature uses only past prices, so nothing from the future leaks in. The 15 features fall into two families:

Within each family the features overlap heavily. Returns over 5, 10 and 21 days share most of the same days, and three volatility windows measure the same jumpiness over different spans. Two things are predicted, each comparing a stock with the other 89 on the same date:

  • Direction: will the stock beat the median stock over the next 10 days? Large-cap returns are close to unpredictable, so little is expected here.
  • Size of the move: will the stock's move (up or down, ignoring the sign) be bigger than the median stock's? Jumpy stocks tend to stay jumpy, so this should be predictable. It serves as a check that the method finds a signal when one is there.

How importance is measured

There are three common ways to ask a trained model which features it uses. Each is given a plain name here, with its usual abbreviation.

  • Split credit (MDI, "mean decrease in impurity"). A decision tree works by splitting the data on one feature at a time. Each split makes the groups more uniform, and the feature used gets credit for that improvement. Adding up the credit over all trees gives each feature's share; the shares add to 100%. It is fast, but it is measured on the same data the model learned from.
  • Scramble test (MDA, "mean decrease in accuracy"). Take data the model has not seen, randomly shuffle one feature's column so it becomes meaningless, and measure how much worse the predictions get. If nothing changes, the model was not using that feature. The damage is measured with log-loss, a score of how wrong the model's predicted probabilities are.
  • Solo test (SFI, "single feature importance"). Train a model on one feature alone and test it on unseen data. No other feature can cover for it, but it also cannot tell when two features say the same thing.

The proposed fix is a group scramble test. First, features are grouped by how closely they move together, using a clustering method (ONC) that also decides how many groups there are. Then all features in a group are shuffled at the same time, so no copy is left for the model to fall back on. In the project analogy, the whole team that knows the task is removed at once.

In model terms: scramble score = log-loss(column shuffled) − log-loss(original), on held-out data. The group test shuffles every column in a group with the same row order. ONC runs k-means on the distance √(½(1 − correlation)) for each possible number of groups and keeps the one where features sit clearly closer to their own group than to any other.

Steps

  1. Build the made-up data with 5 drivers, 30 copies and 5 noise features (10,000 rows).
  2. Score every feature with split credit, the scramble test and the solo test, using a random forest and 5-fold cross-validation (train on 4/5 of the data, test on the other 1/5, five times).
  3. Measure the dilution by scoring the drivers with and without their copies, then repeat on 20 fresh datasets.
  4. Group the features by correlation and score each group with the group scramble test.
  5. Run a sanity check that needs no known answer (Finding 3).
  6. Repeat on real stocks, splitting the dates into 5 blocks in time order. The model is tested on one block and trained on the others, dropping training rows within 15 days of the test block so no 10-day outcome overlaps between the two.

Finding 1 · Copies cut a driver's importance to a sixth

The first look shows the dilution, but not how large it is, because the drivers' undiluted scores are unknown there. Removing the copies gives that number. The same 5 drivers and 5 noise features are scored by the scramble test twice: once alone, once with the 30 copies added. The drivers are identical in both runs. Only the copies change.

The reported importance of a feature depends on how many relatives it has, which is something nobody controls in a real feature list. Adding a 15-day momentum feature next to 10-day and 21-day momentum makes all three look weaker, although the model knows nothing new.

Finding 2 · Testing features as groups recovers the truth

The fix has two steps. First, group the 40 features using only their correlations, the same information as in the first-look heatmap. The grouping method is not told the label or which feature copies which. Second, shuffle each group as a whole and measure the damage.

Forty diluted scores become six scores that match the truth. The grouping step needs no label and no tuning, so it can run on any feature list before the model is trusted. Group split credit is a quick first look, but it still rewards features the trees happen to split on often; the group scramble test is the one to rank by.

Finding 3 · A sanity check that needs no known answer

On real data there is no answer key. One quick check: rotate the features into principal components. These are new, uncorrelated combinations of the features, sorted from the one that explains the most shared movement (PC1) to the least. Because they are uncorrelated, no feature can cover for another. A model that learned something real usually relies on the first few components. A model that only memorised noise has no reason to prefer them.

If a model's credit does not lean toward the main components, its importance scores probably reflect noise. The check is a warning light, not a proof, because a real signal can sit in a small component.

Finding 4 · Past prices predict how much a stock will move, not which way

The same procedure on the 90 stocks. The grouping step splits the 15 features into the two families in the data table: a price trend group (10 features) and a volatility group (5 features). Short and long horizons stay together. Four columns of random numbers are added as a ruler.

Interpretation: price history is useful for forecasting risk (how much a position may swing, how wide a stop or risk limit should be, how expensive options might be), and not useful on its own for choosing which stocks will outperform.

How to prevent it

Five steps make feature importance trustworthy when features overlap. Each comes with what it looked like in this study.

  1. Look at the correlations first. Draw the correlation heatmap of the features before training. Blocks of dark squares are features that will share credit. Here, the five volatility measures form one block.
  2. Group features that move together. Use a clustering method on the correlations so the groups come from the data, not from guesswork. Here the grouping found every driver's copies with no mistakes.
  3. Score groups, not single features. Shuffle each whole group on unseen data. Here this turned a "minor" set of volatility features into the model's main signal.
  4. Add a few random columns as a ruler. Any score close to theirs is zero. Here, a direction score 2.4 times the random columns' still meant nothing; real signals were over 100 times larger.
  5. Check the model can predict at all. If unseen-data accuracy is near a coin flip (AUC near 0.5), there is nothing to rank, whatever the importance chart shows.

Dropping all but one feature from each group is another option. It removes the dilution at the source, but it loses the small extra information each copy may carry, so it is best done after the group test has shown which groups matter.

Use it when

  • Features come in families: several lookback windows, several versions of the same measure.
  • Deciding which features to drop, or explaining what a model relies on.
  • Testing whether a new feature adds anything beyond the existing ones.

Skip it when

  • The features are already unrelated to each other.
  • The model cannot predict better than chance on unseen data.
  • The question is which single member of a group does the work; grouping cannot answer that.

Conclusion

Asking "how much would the model lose without this feature?" gives a misleading answer when the feature has relatives, because the relatives fill the gap. Asking "how much would the model lose without this information?", by grouping similar features and removing each group as a whole, gives the right answer on data where the truth is known. On real stocks it gives a clear one: recent price history describes how much a stock is likely to move, not which way.

Limitations and next steps

  • One made-up design (5 drivers, near-perfect copies). Looser or nonlinear relationships may group less cleanly.
  • Price features only, on 90 of today's large caps, so the stock list leaves out companies that dropped out of the index (survivorship bias). This does not affect the comparison of methods.
  • Five test blocks make t-statistics unstable; more blocks or repeated shuffles would steady them.
  • Next: add company fundamentals to the direction test, test the size target over several horizons, and use the group test to trim the feature list.
